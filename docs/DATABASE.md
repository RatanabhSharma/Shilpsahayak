# Database

The application utilizes Firebase Cloud Firestore as its primary database. Security rules (`firestore.rules`) govern access to these collections based on the user's role (admin vs customer).

## Firestore Collections

- **`users`**: Contains user profiles and role information (admin vs customer).
- **`products`**: The product catalog. Publicly readable, writeable only by admins.
- **`categories`**: Product categories. Publicly readable, writeable only by admins.
- **`orders`**: Customer orders. Customers can read their own orders; admins have full access.
- **`quotes`**: Custom print quotes generated by the slicer service.
- **`filaments`**: The filament catalog (used for pricing). Admin access only.
- **`mail`**: Queue for the Firebase Trigger Email extension to send outbound emails.
- **`settings`**: Application settings. Publicly readable, writeable only by admins.
- **`inquiries`**: Contact form submissions.

## In-Memory & Local Storage (Frontend)
- The Zustand store (`shilp-sahayak-store`) caches certain data in `localStorage`.
- Specifically, the `cart` and `settings` are persisted locally.
- `products`, `orders`, and `quotes` are fetched from Firestore and cached in memory during the session via React Query/Zustand hooks.
